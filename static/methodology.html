How Hermes knows who can change the code

Hermes maps who can upgrade deployed contracts on Base, through every layer between a proxy and the keys behind it, and what else those keys reach. It reads storage and calls functions; it never reads bytecode for bugs. It states what can upgrade a contract, never whether anyone will, and never that a key is compromised.

What is indexed

Addresses come from a hand-curated list and from chain-wide discovery of the three ERC-1967 events (Upgraded, BeaconUpgraded, AdminChanged). Discovery reads 1,000-block windows at fixed positions spread over Base's history and admits at most a few addresses per implementation, beacon or admin. The index is a sample, not a census. Without the cap, clones of a handful of contracts would be most of it. Every count Hermes publishes is within the sample, and each API answer carries its scope.

Classification

Each address's ERC-1967 implementation, admin and beacon slots are read directly, plus the EIP-1822 and ZeppelinOS slots. Implementation and admin set: transparent. Implementation only: UUPS. Beacon: beacon. Admin only: an OP Stack predeploy. Covered kinds are transparent, UUPS, beacon, EIP-1822 and admin-only. Inherited storage, eternal storage, Diamond and the ZeppelinOS slot are recorded and not counted as covered.

The walk follows at most four links and stops on a cycle. An unknown owner anywhere under a Safe makes the whole count unknown, because the unknown one could be a single key.

Unknown is an answer

A missing number is null, never zero. A covered proxy with no root says why: unrecognized_interface, uups_unconfirmed, no_upgrade_path or rpc_undetermined. A root with no key count says why too: truncated, cycle, owners_unknown, roles_unread, account_keys_unread or no_known_key. A call the node would not answer is a third outcome, distinct from a contract answering "no", and never becomes a verdict. Confidence only falls along a walk.

History

Every scan reads both chains at their finalized blocks and keeps the graph it walked: each address's answers, and each edge with the blocks it was first and last seen at and the block it closed. A change between two scans is recorded with both blocks, and bisection over archive state then pins single-read changes (an owner, a threshold, a delay, a signer, a slot) to the first block the new value holds at. A change in how Hermes reads the chain (a new model version) is recorded as a reinterpretation and never shown as the chain moving. "First seen" means first seen by Hermes; nothing before the first scan of an address is in the store.

What a compromise reaches

For any address, Hermes lists the indexed proxies whose upgrade walk passes through it, in three groups: those it controls alone, those whose authority it takes part in without being enough alone (one signer of a 2-of-5), and those where the walk cannot tell. A key is taken on both chains, since one private key signs for its address everywhere. Nothing is added up across groups, and no figure is a dollar figure.
